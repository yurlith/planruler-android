# Этап 2: ревизии планов — отчёт о реализации

Дата: 2026-08-12  
Версия формата проекта: 5

## Результат

PlanRuler теперь заменяет отдельную логическую страницу новой редакцией без потери
старого источника и без перезаписи старых измерений. Реализован полный безопасный
маршрут:

1. Открыть список страниц и выбрать «Заменить текущую страницу».
2. Импортировать PDF, PNG или JPEG; у многостраничного PDF выбрать нужную страницу.
3. Отметить одинаковые точки сначала на старом, затем на новом листе.
4. Две пары строят similarity transform (перенос, поворот, равномерный масштаб).
5. Необязательная третья пара строит affine transform и исправляет перекос скана.
6. После подтверждения старые измерения архивируются, а на новую редакцию создаются
   отдельные копии с новыми ID и статусом `NEEDS_REVIEW`.
7. Пользователь сравнивает листы с помощью наложения и вручную подтверждает каждое
   перенесённое измерение.

## Гарантии данных

- URI, MIME type, исходный номер страницы и геометрия старой и новой редакции
  сохраняются в `PageRevision`.
- `archivedMeasurements` — точный снимок измерений до переноса.
- Перенесённая копия хранит `sourceMeasurementId`, `revisionId`, статус проверки и
  время ручного подтверждения.
- Старый объект не попадает в текущую ведомость и поэтому не удваивает итоговые
  количества.
- Схема 1–4 загружается с безопасными значениями по умолчанию и мигрирует в схему 5.
- При изменении координат калибровка пересчитывается по масштабу transform, но её
  контроль считается неподтверждённым до новой калибровки/проверки пользователем.

## Интерфейс

- В списке страниц виден номер последней ревизии.
- На рабочем поле показывается панель ревизии с прозрачностью старого плана.
- Фильтры: все измерения, измерения ревизии, только требующие проверки.
- В свойствах перенесённого объекта показывается предупреждение и отдельное действие
  «Отметить проверенным».
- Индикатор доверия к масштабу остаётся предупреждающим, пока новая редакция или
  перенесённые измерения не проверены.
- Все новые тексты включены в польскую, английскую, немецкую и совместимую русскую
  локализацию.

## Экспорт

- JSON содержит полную историю источников, alignment, архив и статусы.
- CSV содержит `revision_id`, `review_status`, `source_measurement_id`, `reviewed_at`
  и отдельную секцию `REVISION_LOG`.
- В информационном блоке PDF перед легендой печатаются номер и дата ревизии,
  количество контрольных точек и число непроверенных измерений.
- Для PDF-ревизии экспорт открывает именно URI и номер страницы текущей редакции.

## Автоматические проверки

- Две точки: восстановление переноса, поворота и масштаба.
- Три точки: восстановление affine/skew transform.
- Отказ для совпадающих и коллинеарных точек.
- Перенос только выбранной страницы, новые ID, правильный источник и обязательный
  `NEEDS_REVIEW`.
- Сохранение и восстановление языка, ревизии и статуса после recreation приложения.
- Реальный SAF-маршрут ревизии на Android API 35: импорт двух изображений,
  совмещение, перенос, перезапуск и ручное подтверждение.
- CSV/JSON: присутствие журнала и точный round-trip модели.

Финальный прогон 2026-08-12:

- 50 JVM-тестов: `PASS`, ошибок и пропусков нет;
- 24 инструментальных теста на Android 15 / API 35: `PASS` — 11 app UI/E2E,
  8 document gateway и 5 export gateway;
- Android Lint: 0 ошибок, 30 предупреждений только об обновлении согласованного
  Android/Gradle toolchain;
- статический аудит локализации: 310 ключей у польского и немецкого словарей,

- debug и minified release пересобраны; подписанный тестовым сертификатом

  Android 15 / API 35 (`versionCode 10200`).

## Осознанно не добавлено

Автоматический pixel diff не включён. Он не должен подменять ручное совмещение или
автоматически объявлять перенесённые измерения корректными. Следующий допустимый шаг —
только визуальная маска различий поверх уже проверенного ручного alignment, после
benchmark на реальных сканах и PDF.

## Ручной smoke на телефоне

1. На тестовом проекте создать одно измерение и одну отметку-счётчик.
2. Открыть «Страницы» → «Заменить текущую страницу».
3. Выбрать реальную новую редакцию и поставить две широко разнесённые пары точек.
4. Проверить совпадение старого и нового листа при прозрачности 30–70 %.
5. Убедиться, что фильтр «Требует проверки» показывает обе перенесённые копии.
6. Проверить одну копию вручную и отметить её проверенной; вторая должна остаться в
   фильтре.
7. Перезапустить приложение и убедиться, что редакция, overlay и статусы сохранены.
8. Экспортировать CSV, JSON и PDF и проверить журнал ревизии.

Полный бланк полевой приёмки: `docs/STAGE2_FIELD_ACCEPTANCE_PROTOCOL.md`.
