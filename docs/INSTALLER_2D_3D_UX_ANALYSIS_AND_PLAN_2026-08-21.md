# PlanRuler: анализ 2D/3D и план интерфейса для монтажника

Дата: 21 августа 2026 года.  
Статус: исследование и продуктовая концепция; этапы 1–5 реализованы 21 августа 2026 года.

## 1. Главный вывод

У PlanRuler уже достаточно сильное вычислительное ядро, чтобы не начинать заново.
Основная проблема находится между ядром и пользователем:

- 2D работает как универсальный редактор измерений;
- 3D работает как демонстрация возможностей движка и инженерный редактор;
- монтажнику нужен один последовательный процесс: **что соединяем → откуда и докуда
  измерили → какой маршрут нужен → что отрезать → как собрать → сохранить/передать**.

Целевой продукт не должен выглядеть как упрощённая CAD-система. Его правильная роль:

> Монтажная линейка, которая переводит понятные замеры с объекта или плана в проверенную
> схему, длины резов и список деталей.

3D в этой модели — средство понять и проверить форму. 2D с размерами и список резов —
рабочий результат. Монтажник не должен выбирать режим движка, вводить векторы `dX/dY/dZ`
или разбираться, что такое mesh quality.

## 4. Диагноз текущего 2D

### 4.1 Слишком много режимов вокруг простой задачи

Пользователь одновременно сталкивается с:

- режимом `Редактирование / Просмотр`;
- инструментами `Навигация / Выбор / Длина / Полилиния / Площадь / Угол / Счётчик /
  Заметка / Калибровка`;
- разными реакциями на tap, double tap, long press, drag и pinch;
- скрытыми панелями свойств, слоёв, ведомости, страниц и экспорта.

Для опытного пользователя это мощно. Для монтажника, который открыл приложение впервые,
неясно, нужно ли сначала выбрать `Навигация`, `Выбор` или `Длина`, и почему активный
инструмент рисования иногда выбирает существующий объект.

### 4.2 В режиме редактирования показываются ручки всех объектов

`WorkspaceCanvas.kt` передаёт `showHandles = editable` каждому измерению. В результате
при большом takeoff все вершины становятся управляющими точками одновременно. Это:

- создаёт визуальный шум;
- ухудшает чтение самого плана;
- не показывает, какой объект выбран;
- повышает вероятность случайного изменения соседней линии.

Правильное правило: ручки видит только выбранный объект. Остальные измерения остаются
чистыми линиями с подписями.

### 4.3 Основной результат спрятан

Ведомость и итоги существуют, но открываются через меню/оверлей. На рабочем поле нет
постоянного ответа на два вопроса:

- сколько уже насчитано по текущему материалу;
- какой результат последнего действия.

Монтажнику нужен короткий итог рядом с работой: например `Труба DN20: 24,6 м` и
`последний участок: 2,35 м`, а не отдельный переход к ведомости после каждого сомнения.

### 4.4 Терминология шаблонов остаётся абстрактной

В коде уже есть хорошие стартовые шаблоны. Но интерфейс должен спрашивать не
`Выберите шаблон`, а `Что считаете?` и показывать знакомые карточки:

- подача отопления;
- обратка;
- ХВС;
- ГВС;
- канализация;
- воздуховод;
- кабель;
- площадь стены/пола;
- оборудование/точки.

### 4.5 2D не создаёт монтажную сборку

Измеренная полилиния сохраняется как takeoff-геометрия. У неё нет связи с 3D-цепочкой,
фитингами или монтажным расчётом. Пользователь должен покинуть проект, открыть мастерскую
и повторно ввести данные.

Это главный функциональный разрыв: **план измеряется отдельно, узел рассчитывается отдельно**.

## 5. Диагноз текущего 3D и мастерской

### 5.1 Вход начинается с модели, а не с задачи

В `FabricationWorkshop` по умолчанию открыта секция `MODEL`. Параметры находятся в
отдельной вкладке. Пользователь сначала видит готовый пример DN50/PN16, затем должен понять,
что реальные значения вводятся в другом разделе.

Монтажный сценарий должен начинаться с вопроса и схемы, а модель появляться после первых
достаточных данных.

### 5.2 Четыре режима 3D отражают архитектуру движка

Сейчас есть:

- `Проверено`;
- `Ручной`;
- `Авто`;
- `Параметры`.

Это полезные внутренние состояния, но плохая верхнеуровневая навигация. Монтажник не должен
решать, использовать ли ему solver или manual chain editor. Он должен выбрать тип задачи,
а приложение — применить подходящий метод.

### 5.3 Инженерские поля вместо языка объекта

Самые трудные элементы:

- `X/Y/Z`;
- `dX/dY/dZ` конечного направления;
- `roll`;
- `start frame`;
- `minimum straight`;
- `mesh quality`;
- `radius mode`, предел отводов и параметры профиля в основном процессе.

Замена на монтажный язык:

| Сейчас | Для монтажника |
|---|---|
| X | Вдоль трассы |
| Y | Влево / вправо |
| Z | Подъём / опуск |
| dX/dY/dZ | Куда должен смотреть конец: прямо / влево / вправо / вверх / вниз / назад |
| roll | Поворот отвода по часам или положение в торцевом виде |
| start frame | Начальная точка и направление первой трубы |
| minimum straight | Минимальный допустимый прямой участок, обычно берётся из профиля |
| mesh quality | Автоматическая настройка; убрать из обычного режима |

### 5.4 3D пока нельзя редактировать пальцем

Viewer умеет:

- вращаться;
- масштабироваться;
- панорамироваться;
- выбирать деталь tap-ом.

Но изменение детали происходит только числом в инспекторе. Математика для drag уже есть,
однако она не подключена к ViewModel и canvas. Поэтому 3D выглядит интерактивным, но после
выбора детали пользователь не может потянуть её видимый конец.

### 5.5 Показаны не все рабочие размеры

Текущая сцена показывает общие X/Y/Z и размер выбранной детали. Для изготовления нужны
отдельные группы:

- откуда и докуда был сделан исходный замер;
- общие face-to-face / center-to-center размеры;
- длины прямых участков;
- длины резов;
- takeout фитингов;
- сварочные зазоры;
- углы и направление поворота;
- положение фланца и болтового рисунка в торце;
- DN, наружный диаметр и стенка;
- количество и марки деталей.

В одной перспективной сцене все эти размеры неизбежно накладываются друг на друга. Поэтому
решение — не `показать ещё больше текста в 3D`, а автоматически формировать набор 2D-видов.

### 5.6 Сборка не является частью проекта

`PlanProject` schema 5 хранит документ, измерения, слои, шаблоны и ревизии. Полей для
монтажных расчётов и 3D-цепочек нет.

Монтажная мастерская использует `rememberSaveable`, а 3D-план — локальный `ChainPlanSaver`.
Это позволяет пережить часть UI-пересозданий, но не создаёт полноценную запись проекта.
Также нет штатного экспорта монтажного листа из мастерской.

Последствия:

- расчёт нельзя надёжно найти по объекту через неделю;
- его нельзя связать с замером на плане;
- нет ревизии результата и истории изменения;
- нет единого PDF `план + узел + резы + материалы`;
- невозможно безопасно доказать, по каким входным данным был сделан рез.

## 7. Предлагаемая продуктовая концепция

Рабочее название: **Монтажный узел**.

### 7.1 Два входа, один результат

Пользователь начинает одним из способов:

1. **Из проекта/плана** — выбирает измеренную трассу или две точки.
2. **Быстрый расчёт на объекте** — вводит размеры с рулетки/лазера без плана.

Оба входа создают одинаковую сохраняемую сущность `Монтажный узел` и приводят к одному
экрану результата.

### 7.2 Основной процесс

```text
Новый монтажный узел
  → Что собираем?
  → Как выглядит переход?
  → Выберите точки, между которыми мерили
  → Введите доступные размеры
  → Проверка направления конца
  → Решение
      ├─ Схема и виды
      ├─ Резы
      ├─ Детали
      └─ Проверки
  → Сохранить / PDF / поделиться
```

### 7.3 Типы задач на первом экране

Карточки с простыми картинками:

- прямая вставка;
- плоское смещение двумя отводами;
- пространственное/rolling смещение;
- поворот 90° с выносом;
- обход препятствия;
- разворот;
- ответвление тройником;
- переход диаметра;
- сборка от фланца до фланца;
- свободная сборка — только в разделе `Расширенные`.

Последние три использованных сценария показываются первыми.

## 8. Экран ввода: схема вместо формы

### 8.1 Основной макет телефона

```text
┌──────────────────────────────┐
│ Смещение двумя отводами      │
│ DN50 · 45°             [⋮]  │
├──────────────────────────────┤
│                              │
│   [начало] ══╮               │
│              ╲               │
│               ╰══ [конец]    │
│      ↕ Подъём  [ 500 mm ]    │
│  ↔ Вдоль      [1600 mm ]     │
│                              │
│ [Показывать точки замера]     │
├──────────────────────────────┤
│ Конец смотрит: [→] [↑] [↓]  │
│ Фитинг: [30°] [45°] [90°]   │
├──────────────────────────────┤
│ Предварительный рез P2       │
│              640,1 mm        │
│                [Рассчитать]  │
└──────────────────────────────┘
```

Пользователь нажимает не в поле `X`, а на размерную стрелку на рисунке.

### 8.2 Выбор точек замера

На каждом конце схемы должна быть нажимаемая точка:

- ось трубы;
- наружный край трубы;
- внутренний край трубы;
- торец трубы;
- центр фитинга;
- торец фитинга;
- привалочная плоскость фланца.

Приложение само приводит замер к своей осевой геометрии. Рядом постоянно показывается
фраза, например:

> Введите расстояние от наружного края первой трубы до привалочной плоскости фланца.

Это снижает самый дорогой класс ошибок: правильная формула на неверно понятых исходных
точках.

### 8.3 Обычный и расширенный режим

Обычный режим показывает только:

- тип узла;
- DN/материал/серию;
- понятные пространственные размеры;
- направление конца;
- угол или тип фитинга;
- кнопку расчёта и главный результат.

`Расширенные параметры` содержат:

- ручной takeout;
- собственные размеры фитинга;
- сварочный зазор;
- минимальный прямой участок;
- нестандартный радиус;
- допуски;
- ручную цепочку.

Качество меша в пользовательский интерфейс не выводится: приложение выбирает его само.

## 9. Как представить все размеры и стороны

### 9.1 Набор видов

Для каждого узла автоматически формируются:

1. **Изометрия** — понять общую форму, номера деталей и направление монтажа.
2. **Вид сверху** — размер вдоль трассы и смещение влево/вправо.
3. **Вид сбоку** — подъём/опуск, отметки высоты и уклон.
4. **Вид спереди/справа** — второй пространственный офсет.
5. **Вид с торца** — поворот отвода, clocking и болтовой рисунок фланца.
6. **Монтажный лист** — автоматически собранная страница с нужными видами и таблицами.

Не нужно всегда показывать шесть равноправных кнопок. Приложение выбирает минимальный
достаточный набор:

- плоское смещение: изометрия + один ортогональный вид;
- rolling offset: изометрия + сверху + сбоку + торец;
- фланцевая сборка: дополнительно вид фланца с болтовым кругом;
- тройник: дополнительно вид ветки и её отметка.

### 9.2 Слои размеров

Над схемой переключатель:

- `Монтаж` — размеры, которые надо снять и выставить на объекте;
- `Резка` — длины заготовок, метки реза и зазоры;
- `Детали` — DN, OD, стенка, радиус, takeout, фланцевые размеры;
- `Все` — контрольный инженерный вид.

По умолчанию открывается `Резка` после расчёта и `Монтаж` при проверке исходных данных.

### 9.3 Правила нанесения размеров

- размеры размещаются снаружи контура, а не поверх трубы;
- минимум два уровня размерных цепей: локальные участки и общий габарит;
- подписи не пересекают геометрию и друг друга;
- при нехватке места используются выноски;
- выбранная деталь одинаково подсвечивается во всех видах и в списке резов;
- обозначения `P1/P2/P3`, `E1/E2`, `F1/F2` постоянны во всех экранах и PDF;
- отрицательные координаты не показываются как числа — вместо них `влево`, `вниз`,
  `назад`;
- критический размер можно нажать и открыть `Откуда он взялся` с исходным замером,
  takeout и зазором;
- точность отображения выбирается по единицам и задаче, а не всегда `0.1 mm`.

### 9.4 Цветовая семантика

- синий — исходные размеры с объекта;
- зелёный — подтверждённые длины резов;
- оранжевый — фитинги и монтажные takeout;
- фиолетовый — направление/поворот в пространстве;
- красный — конфликт, недопустимый рез или непроверенный параметр.

Цвет всегда дублируется подписью и формой линии.

## 10. Новый 2D-сценарий

### 10.1 Упростить управление

- один палец на пустом месте — панорамирование, если инструмент не рисует;
- tap по объекту — выбор;
- drag видимой ручки — изменение;
- drag тела выбранного объекта — перемещение;
- два пальца — pan/zoom из любого режима;
- long press — только контекстное меню, не основной путь к свойствам;
- отдельный режим `Просмотр` оставить для защиты от случайных правок, но не делать его
  обязательной частью обычного workflow.

### 10.2 Показ ручек

- ручки только у выбранного измерения;
- для линии — две крупные крайние ручки;
- для полилинии — крайние ручки крупнее промежуточных;
- активная ручка показывает живой размер и изменение `+125 mm`;
- зона попадания больше видимого маркера и зависит от профиля `палец/перчатка/стилус`.

### 10.3 Панель инструментов

Основные кнопки зависят от профессии, но на телефоне их не больше пяти:

- трасса;
- площадь;
- количество;
- заметка;
- ещё.

`Навигация`, `Выбор` и `Калибровка` не должны постоянно занимать равноправные места рядом
с рабочими инструментами. Статус масштаба остаётся наверху и открывает калибровку tap-ом.

### 10.4 Постоянный быстрый итог

Над нижней панелью:

```text
ХВС DN20 · 24,6 м      Последний: 2,35 м
```

Tap открывает ведомость, но сам итог не требует ухода с плана.

### 10.5 Переход из 2D в монтажный узел

После выбора линии или двух точек появляется действие:

`Рассчитать узел`.

Приложение переносит:

- длину в плане;
- выбранный DN/материал из шаблона;
- ссылку на страницу и исходное измерение;
- направление в плане.

Затем спрашивает только недостающие данные: высоту, второй офсет, направление конца и
точки фактического замера.

## 11. Новый 3D-сценарий

### 11.1 3D — проверка, не форма ввода

После получения решения 3D отвечает на вопросы:

- форма соответствует объекту?
- отвод повернулся в нужную сторону?
- конечный фланец смотрит правильно?
- ветка тройника уходит туда, куда надо?
- есть ли самопересечение?

### 11.2 Прямое редактирование

В следующем этапе после нового базового workflow:

- конец трубы тянется вдоль её оси;
- дуга отвода меняет угол;
- торцевой круг задаёт поворот по часам;
- конечная точка трассы перемещается по выбранной плоскости;
- `+` на открытом конце добавляет следующий элемент;
- drag создаёт один шаг undo через уже существующий preview API.

При оси, направленной в камеру, приложение не угадывает движение, а предлагает перейти
на вид сверху/сбоку.

### 11.3 Инспектор выбранной детали

Вместо общего набора полей:

```text
Труба P2
Рез: 640,1 mm
Наружный Ø: 60,3 mm
Стенка: 2,9 mm

[Изменить длину] [Заменить] [Удалить]
```

Для отвода показываются угол, направление поворота, радиус и takeout. Для фланца — DN/PN,
face-to-weld, отверстия и clocking.

## 12. Единая модель данных

Нужна сохраняемая сущность, связанная с проектом, но независимая от UI:

```text
InstallationJob
  id
  projectId?
  name / location / floor / room
  sourceMeasurementIds[]
  taskType
  measurementReferences
  pipeProfile / fittingProfile
  chainPlan3D
  inputDimensions
  catalogVersion
  engineVersion
  resultChecksum
```

Правила:

- сохранять исходные параметры и параметрический план, а не только картинку;

- если контрольная сумма изменилась после обновления каталога/формул, показывать

- хранить ссылки на исходные 2D-измерения;
- экспортировать версию каталога, единицы и точки замера;
- не смешивать монтажные расчёты с CRM-заказом: CRM только ссылается на проект/узел.

### Сценарий D — связь с проектом

1. Создать узел из измерения на плане.

### Целевые метрики beta

- базовый расчёт без помощи: не менее 90%;
- медианное время до списка резов: до 2 минут для готового типа узла;
- правильный выбор точек замера: не менее 90%;
- правильная идентификация нужного реза: 100% в контрольных сценариях;
- возврат к сохранённому расчёту: 100%;
- критическая потеря проекта или узла: 0;
- не более одного обращения к `Расширенным параметрам` в базовом сценарии;
- SUS после теста: целевой ориентир 80+.

## 17. Решение, которое предлагается утвердить

1. Целевая аудитория ближайшего UX — монтажник/бригадир, а не инженер-проектировщик.
2. Основная сущность — сохраняемый `Монтажный узел` внутри проекта.
3. Основной ввод — выбор схемы, точек замера и понятных направлений.
4. 3D — проверка формы и прямое изменение, но не обязательный математический редактор.
5. Основной производственный результат — многовидовой 2D-лист, резы и материалы.
6. Первый прототип делается без изменения движка; сначала проверяется понятность потока.
