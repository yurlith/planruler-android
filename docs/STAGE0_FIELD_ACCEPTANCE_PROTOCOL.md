# PlanRuler — протокол полевой приёмки этапа 0

Этот документ заполняется для сборки `1.0.0-rc3-stage0`.

## 1. Устройства

|---|---:|---:|---|---|---|

Средним считать устройство, близкое к реальному телефону исполнителя, а не флагман.

## 2. Набор документов

Минимум 20 обезличенных файлов:

- не менее 8 векторных PDF;
- не менее 6 PDF-сканов;
- не менее 3 фотографий/изображений;
- не менее 3 многостраничных или тяжёлых документов;
- минимум один повёрнутый JPEG и один PDF с нестандартным размером страницы.

Для каждого файла записать: тип, страницы, размер, способ калибровки, ожидаемую длину,
измеренную длину, ошибку, результат импорта, сохранения, повторного открытия и экспорта.

## 3. Process-death сценарий

Для каждого устройства:

1. Импортировать документ и откалибровать его.
2. Создать минимум пять измерений разных типов.
3. Изменить вершину и единицу отображения.
4. Не нажимая ручное сохранение, выполнить `adb shell am force-stop com.planruler.app`
   либо закрыть процесс через системные настройки.
5. Открыть приложение и проект заново.
6. Сравнить калибровку, пять измерений, изменённую вершину и единицу.
7. Повторить после undo/redo и после контрольного отрезка.

Проход: ни одно подтверждённое изменение не потеряно.

## 4. Производительность pinch/pan

На среднем устройстве использовать один реальный тяжёлый PDF и проект примерно с
2 000 измерений. Выполнить не менее 30 секунд непрерывных pinch/pan после прогрева.

Фиксировать через Macrobenchmark или Perfetto:

- p50 frame time;
- p95 frame time;
- долю кадров более 33 мс;
- максимальный RSS;
- наличие ANR/crash.

Проход: p95 ≤33 мс и нет ANR/crash. Оценка «на глаз плавно» не заменяет метрику.

## 5. Проверка понятности калибровки

Минимум 10 представителей целевой аудитории без предварительного обучения получают задачу:
«Откройте план, установите масштаб по размеру 2 м и проверьте его по размеру 1 м».

Не подсказывать до завершения или отказа. Записать:

- завершил ли самостоятельно;
- время до завершения;
- выбранную единицу;
- заметил ли предупреждение короткого эталона;
- понял ли расхождение контрольного отрезка;
- финальную ошибку измерения.

Проход: минимум 9 из 10 завершают самостоятельно.

## 6. Финальное решение

Этап 0 принят, только если одновременно выполнено:

- ≥90% самостоятельного завершения калибровки;
- медианная ошибка ≤0.5% на векторных планах и ≤1% на качественных сканах;
- нет потери подтверждённых данных после process death;
- p95 pinch/pan ≤33 мс на среднем устройстве;
- 20 реальных документов проходят импорт и экспорт без критических ошибок.

Итог: `[ ] принят`  `[ ] не принят`  `[ ] повторить после исправлений`
