## A. Воспроизводимая сборка из командной строки

**Проблема.** Репозиторий лежит по пути с кириллицей, системная кодовая страница — 1252.
Любой дочерний JVM-процесс (демон Gradle, тестовый воркер) получает путь с `?` и не находит
classpath. Обходной путь я применял вручную и он нигде не зафиксирован.

**Решение.** `scripts/gradle_ascii.ps1`: создаёт junction на ASCII-пути, отображает его в
свободную букву диска через `subst`, запускает `gradlew` оттуда и освобождает букву в
`finally`. Если путь репозитория уже ASCII — запускает напрямую. Все аргументы
прокидываются как есть: `.\scripts\gradle_ascii.ps1 check`.

## B. Разворот на 180° между встречными торцами

**Проблема.** При `dt = -ds` вектор `dt − ds(ds·dt)` вырождается, плоскость поворота не
определена, решатель возвращает `NO_FABRICABLE_ROUTE`.

**Решение.** Плоскость берётся не из направлений, а из смещения: `m = normalize(delta −
ds(delta·ds))`. Новая топология `U_TURN` — два отвода по половине угла (для 180° это два
90°) и три прямых участка:

```
P1 (вдоль ds) — E1(θ/2, крен на m) — P2 (вдоль m) — E2(θ/2) — P3 (вдоль −ds) — F2
```

Направления `{ds, m, −ds}` линейно зависимы, поэтому система решается по двум неизвестным:
сначала `L1` фиксируется минимальным резом и решаются `(L2, L3)`; если `L3` уходит ниже
минимума — фиксируется `L3` и решаются `(L1, L2)`. Строго лобовой случай (смещения нет
вообще) остаётся отказом с явной причиной: обратная линия совпала бы с подающей.

## C. Ветвление тройником в редакторе

**Проблема.** Тройник есть в графе и в сетке, но рецепт цепочки линейный, поэтому с
телефона ветку не построить.

**Решение.** Рецепт становится деревом:

- `ChainStep3D.Tee(rollDeg, branch: List<ChainStep3D>)` — ветка хранится внутри шага;
- адресация шагов — `ChainPath3D(indices)`: `[2]` — второй шаг магистрали, `[2, 0]` — первый
  шаг ветки тройника, стоящего вторым. Вложенность не ограничена искусственно, её ограничивает
  квота деталей;
- команды редактора переходят с индекса на путь: `Append(path)`, `InsertAt`, `Replace`,
  `RemoveAt`;
- `ChainEditorState3D.stepPartIds` становится картой «путь → код детали», поэтому тап по
  детали в сцене по-прежнему находит шаг для правки;
- реплей рекурсивный: тройник ставится портом `run-start`, ветка отыгрывается от порта
  `branch`, магистраль продолжается от `run-end`;
- `AssemblyProfile3D` получает `tee: TeeProfile3D?`; мост берёт размеры из
  `EQUAL_TEE_CATALOG` по DN. Если тройника для диаметра нет — типизированный отказ, а не
  исключение;
- `ChainPlanSaver` учится сохранять дерево (вложенная ветка в скобках);
- в UI появляется «+ тройник» и переключатель активной цепочки: магистраль / ветка T1.

## D. Расчёт вне потока композиции

**Проблема.** `solve`, `fromPlan` и построение сетки выполняются синхронно в композиции.

**Решение.** `Assembly3DViewModel` в `feature/pipe-calculator`:

- владеет режимом, профилем с переопределениями, состоянием редактора, решением и сеткой;
- каждая мутация уходит в `viewModelScope` на `Dispatchers.Default`, состояние публикуется
  через `StateFlow`;
- пересборка сетки — отдельная задача, предыдущая отменяется при новом запросе, поэтому
  быстрые правки не выстраиваются в очередь;
- `ChainPlan3D` остаётся в `rememberSaveable` и подаётся в модель при привязке, поэтому
  переживает и поворот экрана, и смерть процесса; сама модель переживает поворот целиком,
  включая историю undo;
- смена DN больше не сбрасывает цепочку: план переигрывается на новом профиле, и только
  если он там нереализуем — очищается с типизированным сообщением.

Тест-теги и тексты сохраняются, чтобы 25 инструментальных сценариев остались валидными.
