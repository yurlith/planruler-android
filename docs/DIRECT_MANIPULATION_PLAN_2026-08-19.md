# План: прямое редактирование пальцем — 2D-линейки и 3D-сборка

Дата: 2026-08-19. Ветка: `hardening/release-candidate`.
Статус на 21.08.2026: **реализовано**. 2D-редактирование вошло в этап 4, прямые 3D-ручки,
preview/commit, snapping, clocking и действия сцены — в этап 5. Три целевых Android-сценария
прошли на реальных AVD API 26 и 35; подробный итог находится в основном UX-плане.

## A. Планы: линейку нельзя растянуть — причина найдена

### Что происходит

Написал воспроизведение (`PlanRulerDocumentJourneysTest.draggingAnEndpointStretchesTheRulerInsteadOfCreatingANewOne`):
нарисовать линейку, потянуть её конец, посчитать строки в ведомости. Тест падает:

```
Dragging the endpoint created a new ruler instead of stretching the existing one
expected:<1> but was:<2>
```

### Причина

Временная трассировка в момент захвата:

```
hitAt  ... selectable=0 pageMeasurements=0 engine=0 hit=null
dragStart hit=null ... mode=EDIT tool=DISTANCE draft=false measurements=1
```

Хит-тест видит **ноль измерений**, хотя на экране их одно. Логика растягивания в
[WorkspaceScreen.kt:575](../feature/workspace/src/main/kotlin/com/planruler/feature/workspace/WorkspaceScreen.kt#L575)
написана правильно и никогда не срабатывает, потому что `hit` всегда `null`.

`Modifier.pointerInput(key)` перезапускает свой блок только при смене ключа. Ключ —
`listOf(page.documentId, page.pageIndex, tool, mode)`
([WorkspaceCanvas.kt:309](../feature/workspace/src/main/kotlin/com/planruler/feature/workspace/WorkspaceCanvas.kt#L309)).
Рисование линейки не меняет ни один из них, поэтому жестовый блок продолжает работать с
замыканием, захваченным при первом запуске, — со списком измерений, каким он был тогда,
то есть пустым. Дальше срабатывает ветка «палец на пустом месте + инструмент DISTANCE» и
создаётся новая линейка. Ровно то, о чём вы говорите.

Измерения нельзя просто добавить в ключ: тогда блок будет перезапускаться на каждом кадре
предпросмотра и отменять сам жест на середине — именно поэтому в ключ намеренно не входит
выделение (там об этом есть комментарий).

### Решение

1. **Живое состояние вместо захваченного.** Список для хит-теста читается через
   `rememberUpdatedState`, поэтому `hitAt` берёт актуальные измерения в момент вызова, а
   блок жестов не перезапускается. Это же касается `tool` и `mode` — их можно убрать из
   ключа, чтобы смена инструмента не рвала начатый жест.
2. **Прощающая зона захвата.** Промах по линейке при активном DISTANCE молча создаёт новую.
   Ввожу приоритет: если палец опустился в пределах увеличенной зоны (вершина — обычный
   радиус, тело — увеличенный допуск), это правка, а не рисование. Новая линейка начинается
   только при заведомо пустом месте.
3. **Видимые ручки.** У выделенного измерения рисуются ручки на концах — понятно, за что
   тянуть, а не «угадай радиус». Размер берётся из `PlanRulerDimens` (профиль касания:
   стилус/палец/перчатка).
4. **Живой размер при перетаскивании.** Во время растягивания рядом с пальцем показывается
   текущая длина и приращение, а не только после отпускания.

Правки 1–2 — это и есть исправление дефекта; 3–4 делают его заметным для пользователя.

## B. 3D: редактирование сенсором

### Что сейчас

Один палец — орбита, два — панорама и зум, тап — выделение
([ParametricAssembly3DView.kt:163](../feature/pipe-calculator/src/main/kotlin/com/planruler/feature/pipecalculator/ParametricAssembly3DView.kt#L163)).
Изменить что-либо можно **только** числом в инспекторе. Ни ручек, ни перетаскивания, ни
живых размеров у выделенной детали — отсюда ощущение, что «работать невозможно».

### Что делаю

**1. Ручки на выделенной детали.** В экранных координатах рисуются точки захвата:

| Деталь | Ручка | Что меняет |
|---|---|---|
| Труба | конец | длину (растянуть/стянуть) |
| Отвод | конец дуги | угол |
| Отвод | кольцо вокруг оси | крен (поворот плоскости) |
| Переход | конец | длину |
| Начало цепочки | маркер старта | положение всей трассы |

**2. Захват решает, что делать.** Как и на плане: если палец опустился на ручку — правка,
иначе — орбита. Один жестовый обработчик, разветвление по хит-тесту в момент нажатия.

**3. Экран → миллиметры.** Смещение пальца проецируется на ось детали в мировых координатах
и переводится в миллиметры через масштаб проектора. Это чистая функция без Compose —
покрывается обычными JVM-тестами.

**4. Живой размер всегда.** У выделенной детали постоянно висит выноска с реальным размером
(длина / угол / диаметр), при перетаскивании она обновляется вместе с приращением.
Дополнительно — габарит всей сборки, чтобы соотношения были видны без выделения.

**5. Удаление и добавление из сцены.** Долгое нажатие на деталь — удалить/вставить перед,
плюс кнопка «+» на открытом конце. Сейчас это доступно только в инспекторе.

**6. Привязки.** Длина липнет к круглым значениям (5/10/25 мм), угол — к разрешённым
каталогом углам. Без привязок пальцем не попасть в 45°.

### Что нужно добавить в движок

Одно, но важное. Сейчас любая правка идёт через `ChainEditor3D.execute`, и **каждый вызов
кладёт запись в стек отмены**. Перетаскивание — это десятки правок в секунду, стек мгновенно
забьётся, а «отменить» перестанет означать «отменить перетаскивание».

Ввожу превью-путь, зеркальный тому, что уже есть в 2D-движке (`previewVertex` / `commitEdit`):

```kotlin
fun preview(state, command): Fabrication3DResult<ChainEditorState3D>   // без записи в undo
fun commitPreview(state): Fabrication3DResult<ChainEditorState3D>      // одна запись за жест
fun cancelPreview(state): Fabrication3DResult<ChainEditorState3D>
```

Одно перетаскивание = одна запись отмены. Отказ по правилам (короче минимального реза, угол
вне окна) при этом остаётся типизированным и просто не даёт ручке уйти дальше.

### Производительность

Сетка пересобирается на каждое изменение. На время перетаскивания качество опускается до
`DRAFT` и возвращается на отпускании; пересборка уже идёт фоновой задачей с отменой
предыдущей, так что кадры не выстраиваются в очередь.

## D. Проверка

- Воспроизведение растягивания линейки (уже написано, сейчас падает) — должно зеленеть.
- Новый тест: растягивание не плодит линейки при десяти перетаскиваниях подряд.
- Новый тест: смена инструмента в середине жеста не рвёт его.
- JVM: превью не пишет в стек отмены, одно перетаскивание — одна запись.
- JVM: проекция «экран → мм» на всех четырёх ракурсах и в обеих проекциях.
- Эмулятор: труба тянется за конец, угол отвода меняется, крен вращается, размер виден в
  процессе, деталь удаляется из сцены.
- Каждый регрессионный тест проверяется на способность падать без правки.
